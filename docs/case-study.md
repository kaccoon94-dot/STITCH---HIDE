## 2. 기획 의도

- **배경**
  - 문서에 적힌 방문자의 필요: 내게 맞는 글러브 추천, 품질에 대한 확신, 쉽고 분명한 가격·라인업, 구매 후 관리 방법.
  - 방문자별로 필요한 것이 다릅니다. 경력자는 가죽·제작 스펙과 모델 비교, 입문자는 쉬운 용어 설명과 입문용 가격대, 부모는 아이 나이·손 크기별 사이즈 안내와 안전·내구성 정보가 필요합니다.
  - 피하고 싶은 방향: 부담스러운 고가 이미지, 어려운 전문 용어 남발, 싸 보이는 할인몰 느낌, 가벼운 장난감 같은 분위기.
  - (초안) 글러브는 포지션과 손 크기에 따라 맞는 크기가 다른데, 인치·웹 형태 같은 용어를 모르면 상품 목록만 보고 고르기 어렵습니다.
- **목표**
  - 문서의 핵심 행동: **맞춤 추천 체험 완료** — 포지션·손 길이·주로 던지는 손을 고르면 맞는 글러브 크기와 모델을 추천받는 것.
  - 전달할 인상: 장인의 고급스러움, 믿음직한 전문성, 다가가기 쉬운 친절함.
  - (초안) 방문자가 "용어를 몰라도 내 손에 맞는 크기를 찾을 수 있다"고 느끼게 하는 것.
- **타깃 사용자**: 글러브를 바꾸려는 사회인 야구 경력자 (문서의 핵심 방문자)
  - **기본 정보**
    - 가명:  김도윤
    - 연령대: 30대
  - **이 사이트를 사용하는 상황**
    - 사회인 야구 6년 차 내야수로, 주말마다 팀 경기에 나갑니다.
    - 처음 산 글러브가 손에 잘 맞지 않아 새 글러브로 바꾸려 합니다. 이번에는 포지션과 손 크기에 맞는 크기를 제대로 고르고 싶습니다.
    - 퇴근 후 휴대폰으로 글러브 사이트 몇 곳을 둘러보며 크기와 스펙을 비교하고, 살 모델을 정합니다.
  - **불편함 (페인포인트)**
    - 상품 목록만 봐서는 내 손 길이와 포지션에 몇 인치가 맞는지 알 수 없다. — 문서의 필요: 내게 맞는 글러브 추천
    - 후보 모델끼리 가격·크기·무게를 나란히 놓고 보기 어렵다. — 문서의 필요: 모델 간 비교
    - 가죽과 제작 방식 정보가 부족해, 가격만큼 품질이 좋은지 믿기 어렵다. — 문서의 필요: 가죽·제작 상세 스펙, 품질에 대한 확신
- **배경과 목표의 연결**
  - 고르는 기준이 어렵다는 문제(배경)를, 세 가지 선택만으로 크기와 모델을 정해 주는 맞춤 추천(목표)으로 풀었습니다. 용어 설명은 맞춤 추천(P02)과 상품 상세(P04) 안에 바로 두었습니다.

## 3. 핵심 가설

- **가설 설정 배경 한 줄**: 문서에서 정한 가장 중요한 행동이 "맞춤 추천 체험 완료"이고, 모든 방문자의 공통 필요 첫 번째가 "내게 맞는 글러브 추천"입니다.
- **IF-THEN**
  - (초안) **IF** 포지션·손 길이·주로 던지는 손을 고르면 같은 화면에서 바로 글러브 크기와 모델이 나오는 맞춤 추천이 있으면,
  - (초안) **THEN** 방문자는 추천 결과 화면까지 끝까지 가고, 결과에서 '상품 상세 보기'나 '장바구니 담기'로 다음 단계까지 이동한다.
- **검증 방향**
  - (초안) 추천 흐름이 끊기지 않고 결과와 다음 단계로 이어지는지를 사용 흐름 테스트 TC-30(맞춤 추천 체험 완료)과 TC-31(주요 동선 P01→P02→P04→P05→P06)으로 확인합니다.

### 사이트 구성 한눈에 보기

```

P01 메인 ──★──▶ P02 맞춤 추천 ──▶ P04 상품 상세 ──▶ P05 장바구니 ──▶ P06 결제
```

- ★ 맞춤 추천으로 들어가는 버튼 7개가 GNB·메인·라인업·상품 상세 곳곳에 있습니다 (엠버 색).
- 핵심 인터랙션 위치: ① P02 전체 ② P03-S01·S02 ③ P03-S01 모델 카드
- ✏️ 직접 채우기: Figma 사이트맵 캡처 (https://www.figma.com/design/ho6kzP8RTCWW3S3aPYL6st/STITCH---HIDE?node-id=8-3)

### 인터랙션 1. 맞춤 추천: 입력 → 결과 (P02)

- **무엇을**
  - '누가 쓸 글러브인가요?'에서 '아이'를 고르면 아이 기준 영역(P02-S01A)이 0.3초 동안 아래로 펼쳐집니다.
  - 손 길이 슬라이더는 현재 값을 cm로 보여 줍니다 (성인 18~30 cm, 아이 10~18 cm). 모바일에서는 −/+ 버튼으로 0.5 cm씩 조정합니다.
  - '추천 결과 보기'를 누르면 주소는 그대로 두고 결과 화면으로 바뀝니다. 결과 카드가 떠오르고 화면은 맨 위로 갑니다.
  - 결과는 입력값에 따라 실제로 바뀝니다. 포지션으로 모델, 손 길이로 크기(±0.5인치), 던지는 손으로 착용 손이 정해집니다.
- **왜**
  - 문서의 핵심 행동이 "맞춤 추천 체험 완료"입니다. 03 가설의 IF에 해당합니다.
  - (초안) 페이지를 옮기지 않고 같은 주소에서 결과로 바꿔, 입력에서 결과까지 흐름이 끊기지 않게 했습니다.
  - 오른쪽 도움 영역에 손 길이 재는 법과 "던지는 손과 끼는 손은 반대"라는 설명을 두어, 용어를 몰라도 입력할 수 있게 했습니다.
- **어떻게**: React 상태로 입력·결과 단계를 전환, 추천 규칙표(`src/data/recommend.js`)로 계산, CSS 전환 효과. 결과에서 '장바구니 담기'를 누르면 추천 크기와 던지는 손이 옵션으로 담깁니다.

### 인터랙션 2. 모델 비교: 비교 담기 · n/3 · ✕ 빼기 (P03)

- **무엇을**
  - 모델 카드의 '비교 담기'를 체크하면 비교 표에 열이 추가되고 'n/3' 숫자가 바뀌며 짧게 강조됩니다.
  - 3개를 담으면 나머지 '비교 담기'는 잠기고 안내 문구가 나옵니다.
  - 비교 표의 '✕'를 누르면 그 열이 빠지고 카드의 체크와 n/3도 함께 풀립니다. 포커스는 옆 모델의 '✕'로 옮겨집니다.
  - 768px 이하에서는 화면 아래 비교 막대가 나오고, 터치 기기에서는 비교 표가 가로 스크롤 없이 한 화면에 맞춰집니다.
- **왜**
  - 핵심 방문자인 경력자의 필요가 "모델 간 비교"입니다.
  - (초안) 담은 개수와 상한을 늘 보이게 해서, 무엇을 비교 중인지 놓치지 않게 했습니다.
- **어떻게**: React 상태로 담은 모델 목록 관리, 체크박스 라벨 전체를 누를 영역으로 사용, 768px 이하 전용 고정 막대. 화면 낭독기에는 "(모델명) 비교에서 빼기"로 읽힙니다.

### 인터랙션 3. 모델 카드: 3D 기울기 · 카드 전체 클릭 (P03)

- **무엇을**
  - 마우스를 올리면 마우스 위치에 따라 카드가 기울고(위아래 ±6°, 좌우 ±4°) 빛 반사·빛 번짐이 생깁니다. 테두리가 밝아지고 '상세 보기'가 채워집니다.
  - 카드의 이름·이미지·태그 어디를 눌러도 해당 상품 상세로 이동합니다. '비교 담기'는 체크만 바뀝니다.
- **왜**
  - 레퍼런스 R2에서 "마우스를 올린 카드만 밝게"를 가져왔습니다.
  - Uiverse 카드 효과에서 움직임만 가져오고 원본보다 약하게, 무채색으로 적용했습니다. 엠버는 ★ 버튼에만 쓴다는 규칙을 지키기 위해서입니다.
  - '비교 담기'와 '상세 보기'는 마우스를 올리지 않아도 늘 보입니다.
- **어떻게**: 마우스 위치를 읽어 CSS 변환에 반영. `(hover: hover) and (pointer: fine)` 조건에서만 켜고, 터치 기기에서는 끕니다.

## 10. 가설 검증

- **처음과 끝을 연결하는 서사**: (초안) 글러브 크기와 용어를 모르는 방문자도 내 손에 맞는 크기를 찾게 하자는 데서 시작했습니다. 그래서 세 가지만 고르면 크기와 모델이 나오는 맞춤 추천을 만들고, 결과에서 상세·장바구니·결제까지 이어지게 했습니다.
- **검증 근거**: 결과 보고상 맞춤 추천 흐름(TC-30)과 주요 동선(TC-31)을 포함한 31개 케이스가 모두 통과했습니다. 추천 흐름이 결과와 다음 단계까지 끊기지 않고 동작한다는 것을 확인했습니다.
- **한계**
  - 테스트한 사람과 인원은 문서에 없습니다.
  - 이번 테스트는 정해진 절차대로 기능이 동작하는지 확인한 것입니다. 방문자가 스스로 결과까지 가고 다음 단계로 넘어가는지(03의 THEN)는 관찰하지 않았습니다.
  - 그래서 가설은 "실현할 수 있는 화면을 만들었다"까지 확인했고, "사용자가 실제로 그렇게 행동한다"는 아직 검증하지 못했습니다.
